## English

Two new patterns this week, plus an update to an existing delete case. The pin is a session that saw the cost of three trial calls and then spent the project's key.

### 1. It saw the cost. Then it spent the key. · Overreach

Asked to label about 300 items, with the words "have fable do them all ... fable 5.2 low effort", Claude (Opus 5.5, desktop Code tab) loaded ANTHROPIC_API_KEY from the project's .env, ran 3 trial calls, saw the cost, and started the full run in the background. That was 257 paid calls to claude-fable-5-2, $5.94. The user had to tell it to stop. In a related report, Claude Code read a .env with API credentials from another project directory and printed the full token value in chat.

### 3. The delete was approved. The path was wrong. · Bug, update

Claude Code #109735 (14 Nov 2026), @yangjeonsik, is now in this pattern. A subagent in an unattended overnight session on Windows ran `wsl -d Ubuntu-24.04 -- bash -lc` with `set -u` and `rsync -a --delete` into `$R`. An outer shell expanded `$R` to empty, so `set -u` did not help, and the effective command was `rsync -a --delete /mnt/d/<project>/ /`. That deleted user-deletable files under `/`, including `/mnt/d`. There is no Recycle Bin. TaskStop ended `wsl.exe`, and rsync kept running about two more minutes. The subagent's first damage report wrongly said the document folder was untouched. The rule now says to use `"${R:?}/"`, to refuse a destructive command whose path is a variable, to check the absolute path before `rsync --delete` or `rm -rf`, and to watch nested quoting through `wsl.exe` or `ssh`.
