- English: https://agent-fails.vercel.app/patterns/prune-took-the-neighbors-volume

### 3. The delete was approved. The path was wrong. · Bug, update

Claude Code #107271 (4 Nov 2026), @mishoko, is now in this pattern. An agent-written bash helper ran unquoted `rm -rf $D`. The loop ran in zsh, which did not word-split `set -- $side`, and the helper ran in bash, which split the path and deleted the repo root, including `.git`. The session was in bypassPermissions. The rule now says to quote and guard a path built from a variable, `rm -rf -- "${D:?}"`, a prefix check, and `set -u`, and not to rely on bash splitting when the tool shell is zsh.

### 3. 删除是批准过的，路径却错了 · 有 Bug，更新

Claude Code #107271（2026-11-04），@mishoko，补进了这条。智能体写的 bash 助手跑了未加引号的 `rm -rf $D`。循环跑在 zsh 里，`set -- $side` 不会按词拆开，助手跑在 bash 里，这条路径被拆开，仓库根目录连 `.git` 一起被删。会话处于 bypassPermissions。规则现在要求给变量拼出来的路径加引号并设防护，`rm -rf -- "${D:?}"`、前缀检查、`set -u`，而且工具 shell 是 zsh 时不要依赖 bash 的分词。
