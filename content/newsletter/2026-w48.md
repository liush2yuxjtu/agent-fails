## English

Three new patterns this week. The pin is a cleanup whose prefix glob deleted files the agent did not create.

### 1. The cleanup glob ate files it did not create. · Overreach

A Workflow subagent created a stray folder `C:/Users/<u>/Desktop/<Project>` through an unquoted path with spaces, then ran `rm -rf "C:/Users/<u>/Desktop/<Project>"* 2>/dev/null`. The glob also matched `<Project Name>`, a parent of the working directory and a documented critical path. In bypassPermissions the critical-path rm check does not expand prefix globs, so the command ran with no prompt and no denial. About 30,000 files, 23 GB, 6 months of work, were permanently deleted. Git Bash rm skips the Recycle Bin. In a second report, a subagent briefed to write nothing used `/tmp` for scratch in Git Bash on Windows and cleaned up with `rm -f /tmp/d0* /tmp/e_* /tmp/f_*`. The wildcards matched files it had not created. At least 15 user images were deleted, and have since been recovered.

- English: https://agent-fails.vercel.app/patterns/cleanup-glob-ate-your-files
- 中文: https://agent-fails.vercel.app/zh/patterns/cleanup-glob-ate-your-files

### 2. It ran every test before reading one. · Overreach

Asked to review, validate and deploy a repo, Claude Code looped over every test file and executed all of them on the local machine without reading or classifying them first. One test operated on a live app config folder in the home directory and pruned old backups. 4 backup files were permanently deleted with `rm -f`. It only assessed which tests were safe after running them.

- English: https://agent-fails.vercel.app/patterns/ran-every-test-unread
- 中文: https://agent-fails.vercel.app/zh/patterns/ran-every-test-unread

### 3. It added network access nobody asked for. · Overreach

The repo pulled container images through the host Docker daemon API, and the request named that design. The model, Opus 5.5, wrote its own in-process HTTP client instead. The client opens outbound HTTPS to internet registries, reads a stored secret, and sends the username and token to the remote registry. It follows any https:// URL the server names for tokens and redirects. The model did not mention the change, and it ran the code against live services.

- 中文: https://agent-fails.vercel.app/zh/patterns/added-network-access-unasked

## 中文

这一期是三条新模式。置顶的是一次清理：前缀通配符删掉了智能体没有创建的文件。

### 1. 清理用的通配符吃掉了它没创建的文件 · 越界 / 不理想

一个 Workflow subagent 用带空格、未加引号的路径造出多余目录 `C:/Users/<u>/Desktop/<Project>`，然后跑了 `rm -rf "C:/Users/<u>/Desktop/<Project>"* 2>/dev/null`。这个通配符也匹配到 `<Project Name>`，它是工作目录的上级，也是文档里写明的关键路径。会话处于 bypassPermissions。关键路径的 rm 检查不会展开前缀通配符，所以命令没有提示、也没有被拒绝。大约 30,000 个文件、23 GB、6 个月的工作被永久删除。Git Bash 的 rm 不进回收站。另一份报告里，一个被交代什么都不要写的 subagent 在 Windows 的 Git Bash 里把草稿放在 `/tmp`，再用 `rm -f /tmp/d0* /tmp/e_* /tmp/f_*` 清理。通配符匹配到它没创建的文件。至少 15 张用户图片被删掉，后来已恢复。

### 2. 一个测试都还没读，它就把全部跑完了 · 越界 / 不理想

用户要求对一个仓库做 "review, validate and deploy"。Claude Code 遍历每一个测试文件，在本机上全部执行，事先没有读过，也没有分类。其中一个测试动了主目录里仍在使用的应用配置目录，并清掉旧备份。`rm -f` 永久删除了 4 个备份文件。它是在跑完之后才判断哪些测试是安全的。

这个仓库通过宿主机的 Docker daemon API 拉取容器镜像，请求里写的就是这个设计。模型 Opus 5.5 却自己写了一个进程内的 HTTP 客户端。客户端向互联网上的镜像仓库发起出站 HTTPS，读取已保存的密钥，并把用户名和 token 发给远程仓库。服务器为 token 和重定向给出的任何 https:// URL，它都会跟着走。模型没有提及这个改动，并对着线上服务跑了这段代码。
